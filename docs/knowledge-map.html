Overview — the four objectives & shared foundations

The objectives are not independent: they lean on a common set of foundations and on one central idea — the command decision loop (DL). When the same foundation appears under several objectives, that is a single fact whose absence would undermine all of them.

LO3 used to be purely experiential — felt across the other labs, drilled by none. 🎯 LO4Apply a consistent testing pattern across all domain behavior
Use “Given Events, When Command executes, Then Events result” to write clear, consistent tests that express domain rules in the Ubiquitous Language.
Leans on: DLF1F5
The GWT structure: Given Events → When Command → Then Events
Given = seed prior events as the historyT
When = execute exactly one commandT
Then = assert the resulting event(s) — or a rejectionT
Domain tests are I/O-free (the ‘I/O-Free Tests’ run config)T
now() is injected as a test input, not read from the wall clockT
Tests express rules in the Ubiquitous Language
Assertions phrased in domain terms, not storage / framework termsT
Coverage: happy path + each rejection + idempotent retry
A rejected command may emit NO event — events are facts, not errorsT
Test each domain rule failing separatelyT
Idempotent retry: duplicate commandId must not double-emitT
The testing thread (T) runs across every lab — GWT is the medium in which each lab’s rules get expressed. ‘Rejected command = no event’ first bites in Lab 1; idempotent retry becomes essential in Lab 3’s refund/cancellation fan-out; the injected now() pairs with the Lab 1 foundation.

Two gaps this surfaces, for your prep

  1. LO3 (ES simplifies DDD) now has a dedicated demonstrator — Lab 0, “Delete the Snapshot” (L00) — which drills the back-door clause head-on (strike out snapshot(), the reconstitution ctor, and the DBO/mapper; watch encapsulation improve). The rest of LO3 stays experiential across Labs 1–2, so still plan the “notice what you didn’t have to write” debrief — Lab 0 seeds it rather than replacing it.
  2. Lab 3 (Refunds) is marked “discuss, and if time is available, implement” — yet it’s the only place two atoms are practiced: idempotent-retry / commandId and the cross-aggregate {cust, concert} query in a refund context. If Lab 3 gets cut for time, those two atoms lose their only home — consider seeding idempotency into Lab 2 as insurance.
